# Game Brief: Night Shift <<

**One-sentence pitch:** CPU 안에서 야간 근무하는 작은 로봇이 비트 줄을 `<<` `>>`로 밀어 발판을 옮기고 출구까지 길을 만드는 퍼즐 게임.

## 세계관 — 야간 근무조
- 설정: 낮 연산이 끝난 CPU. 야간 근무조 정비 로봇이 비트 줄을 밀어 길을 만든다.
- 용어 매핑: 비트 줄 = 작업 라인, 1 = 발판, 시프트 = 라인 교대(shift), 출구 = 퇴근 지점, 버그 칸 = 현장 위험물, 방화벽 = 통제 구역, 로봇 여러 대 = 근무조(로봇별 색 = 조 색).
- 표현 범위: 이름·색·안내문 한 줄로만 드러낸다. 스토리·대사·일지는 만들지 않는다(범위 밖 유지).
- 안내문 톤: 영어, 근무 메모 느낌의 한 줄 (예: "Line 2 is stuck. Shift it.").

## Core loop
- 보드의 비트 줄(1 = 발판, 0 = 빈칸)을 보고 길을 계산한다.
- 로봇을 걷게 하고(좌우·아래), 줄을 한 칸씩 밀어(`<<` `>>`) 발판을 옮긴다.
- 시프트 횟수 제한 안에 출구에 도달하면 클리어, 실수하면 되돌리기·재시작으로 다시 푼다.

## Player goal & fail state — what "working" looks like
- 목표: 시프트 횟수 제한 안에 출구 칸에 도달한다. 튜토리얼 스테이지의 안내만으로 모든 스테이지를 순서대로 풀 수 있어야 한다.
- 실패: 로봇이 줄 끝 밖으로 밀려나 추락하면 즉시 재시작. 횟수를 다 쓰고도 출구에 못 가면 되돌리기 또는 재시작.

## MVP — what must exist to be the game
- 8칸 줄 2~3개를 그리는 보드와 줄별 10진수 표시
- 좌우 시프트와 끝에서의 비트 소실
- 로봇 걷기·내려가기, 줄과 함께 밀리기, 추락 판정
- 시프트 횟수 제한과 남은 횟수 표시
- 되돌리기(Undo)와 재시작
- 출구 도달 판정과 스테이지 5개 순차 진행 (`StageData`)
- itch.io용 WebGL 빌드 확인

## 다음 단계 — 플레이테스트 2026-11-02 반영
근거: `production/qa/playtests/playtest-2026-11-02-tester1.md` (처음 하는 테스터에게 난이도가 높음, 장애물 기믹 요청).

- 튜토리얼: 스테이지 1 앞에 튜토리얼 스테이지 2~3개. 스테이지마다 안내문 한 줄(규칙만 설명, 키는 설명하지 않음). 조작키는 화면 하단에 항상 표시. 문구는 영어.
- 제한값: 시프트 제한 = 최소 횟수 + 1~2회 여유. 최소 횟수(par)는 따로 표시.
- 버그 칸: 보드 좌표에 고정된 위험 칸. 로봇이 걷기, 내려가기, 줄에 실려 밀리기 중 어떤 방식으로든 그 칸에 들어가면 추락과 같은 실패.
- 방화벽: 보드 좌표에 고정된 벽. 걷기·내려가기로는 들어갈 수 없다. 줄에 실려 밀리면 통과하고, 벽 칸 위에서 멈추면 서 있을 수 있다(걸어서 나가는 것만 막는다).
- 잠긴 줄: 밀 수 없는 줄.
- 장애물마다 소개 스테이지 1개 + 활용 스테이지 1~2개. 모든 스테이지는 BFS로 최소 횟수를 검증한다.

## 다음 단계 — 여러 로봇 (교대 조종)
- 등장: 초반 스테이지(기존 14개: 튜토리얼 3개 + 스테이지 11개, 장애물 소개·활용 포함)는 로봇 1대. 장애물이 모두 나온 뒤의 특정 스테이지만 로봇 2대 또는 3대를 쓴다. 로봇 수는 스테이지마다 정한다.
- 조종: `Q`로 조종 대상을 차례로 바꾼다(0 → 1 → 2 → 0). 걷기·내려가기는 선택된 로봇만 한다. 줄 시프트는 공유라서 줄 위의 모든 로봇이 같이 밀린다.
- 클리어: 로봇마다 자기 색의 출구가 있고, 모든 로봇이 자기 출구에 서 있어야 클리어.
- 실패: 어느 한 로봇이라도 추락하거나 버그 칸에 들어가면 즉시 실패.
- 제한: 시프트 횟수 제한과 par는 모든 로봇 합산 하나로 센다. `Q` 전환은 횟수를 쓰지 않는다.
- 되돌리기: 선택된 로봇도 상태에 포함해서 되돌린다.
- 겹침: 로봇끼리 같은 칸에 들어갈 수 없다. 걷기·내려가기로 다른 로봇이 있는 칸으로는 이동하지 않는다(실패가 아니라 이동 무시, 방화벽과 같은 방식). 시프트는 같은 줄의 로봇을 같이 밀어 겹침이 생기지 않는다.
- 방화벽·버그 칸은 모든 로봇에게 똑같이 적용된다.

### MVP (이 확장분, 6개)
- 로봇 여러 대(최대 3)를 상태에 담는 `BoardLogic` 확장 (로봇별 위치·출구, 선택 로봇)
- `Q` 전환과 선택 로봇 표시 (로봇별 색 + 테두리)
- 모든 로봇 출구 도달 판정, 한 대라도 추락·버그 칸이면 실패
- Undo·재시작에 선택 로봇 포함
- BFS 검증을 여러 로봇 상태로 확장 (par 계산, 3대도 에디터에서 몇 초 안)
- 2대 소개 스테이지 1개 + 2대 활용 2~3개 + 3대 스테이지 1~2개(맨 끝), 안내문 한 줄

### 제외 (이번엔 안 함)
- 동시 조종, 로봇별 다른 이동 규칙
- 로봇끼리 밀기, 4대 이상
- 기존 14개 스테이지 변경 (로봇 1대로 그대로 유지)

### 순서 (위험한 것부터)
1. 순수 C#에서 `BoardLogic` + BFS를 여러 로봇으로 확장하고 테스트 (3대 BFS 성능이 가장 큰 위험)
2. `BoardView`, 입력(`Q`, 줄 밀기 `A`/`D`), 선택 표시
3. 소개·활용 스테이지 입력과 BFS 검증, WebGL 확인

## 다음 단계 — 차별화: 숫자가 지형이다
### 1. 숫자 잠금
- 스테이지에 잠금 조건 목록을 둔다: (줄 번호, 목표 10진수). 예: "Line 2 = 12".
- 클리어 = 모든 로봇이 자기 출구에 있고 + 그 순간 모든 잠금 조건이 참. 출구에 선 뒤 시프트로 조건을 맞춰도 클리어.
- 잠금이 없는 스테이지는 지금과 똑같다(기존 20개 그대로).
- 잠긴 출구는 표시가 다르고, 조건 숫자를 출구 옆에 보여준다.

### 2. 시프트 = 근무 교대 (표현만)
- 남은 시프트 수를 "남은 근무 시간"으로 표시한다(예: 시계 아이콘 + 숫자).
- 0이 되면 "Dawn." 메시지를 띄운다. 규칙은 그대로다(되돌리기·재시작 선택).

### 3. 로봇이 비트를 덮는다
- 줄의 10진수 값을 계산할 때, 로봇이 서 있는 칸은 0으로 센다(로봇이 그 칸의 비트를 덮는다). 로봇은 항상 1인 칸 위에 서므로 값은 줄어든다. 예: 10110011 = 179에서 맨 왼쪽 칸에 로봇이 서면 51.
- 지형 판정(걷기·추락·발판)에는 영향이 없다. 값 표시와 숫자 잠금에만 쓴다. 로봇이 걸으면 덮이는 칸이 따라 움직여 값이 바뀐다.
- 스테이지별 스위치(기본 꺼짐)다. 화면의 줄별 10진수 표시도 덮은 값으로 보여준다.
- 소개 스테이지 1개 + 활용 1개로 시험하고, 플레이테스트에서 헷갈리면 뺀다.
- 처음 안("로봇이 선 칸을 1로 센다")은 폐기: 로봇은 항상 1 위에 서 있어서 값이 절대 바뀌지 않는다(20개 스테이지의 도달 가능한 약 12만 상태를 모두 확인).

### MVP (이 확장분, 5개)
- `StageData`에 잠금 조건 목록, `BoardLogic`에 로봇 덮기 줄 값 계산·잠금 판정
- BFS(`StageSolver`)에 잠금 조건 반영
- 잠긴 출구 표시와 조건 숫자, 줄 값 표시에 로봇 덮기 반영
- 근무 시간 표시 + Dawn 메시지
- 숫자 잠금 소개 1 + 활용 2, 로봇 덮기 소개 1 + 활용 1 (맨 끝에 추가)

### 순서 (위험한 것부터)
1. 순수 C#: 로봇 덮기 값 계산, 잠금 판정, BFS 반영 + 테스트
2. 표시: 잠긴 출구, 줄 값, 근무 시간, Dawn
3. 스테이지 입력과 BFS 검증, WebGL 확인

## 후보 — 구현 보류
- 스테이지 = 숫자 코드: 줄 값을 이어 붙인 코드(예: 12-200-7)로 스테이지를 만들고 공유. 타이틀에서 입력. 잼 이후 검토.
- 휘발성 칸: 로봇이 밟고 떠나면 그 비트가 0이 된다.
- 클럭 줄: 플레이어가 아무 줄이나 밀 때마다 이 줄도 한 칸 자동으로 밀린다(자동 시프트 때도 추락·버그 칸 판정).
- 단방향 줄: `<<` 또는 `>>` 한쪽으로만 밀 수 있다.
- 무거운 줄: 한 번 밀 때 시프트 2회를 쓴다.
